<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| (none introduced) | Both files are static HTML with no input of any kind — no forms, no URL-parameter reads, no `fetch`, no JS beyond the shared `coins.js` include. |
| `localStorage` → `#coin-counter` text | `coins.js` reads the user's own `tapvocab_coins` value and writes it into an element. Pre-existing behaviour on 10+ other pages; this plan only adds two more consumers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-04 | Tampering (DOM XSS) | the 14 hardcoded anchor `href` values | accept | Every URL is a literal authored in the file. Nothing user-supplied is interpolated into markup on either page. There is no sink to attack. |
| T-24-05 | Tampering | `coins.js` writing a `localStorage` value into `#coin-counter` | accept | The value is the user's own coin balance in their own browser; forging it self-grants game lives, which the app already offers via a Reset button. `coins.js` is unchanged by this plan. |
| T-24-06 | Spoofing / phishing (off-origin script or link injection) | new `<script src>` / `<link href>` on the two pages | mitigate | Charter rule: zero external dependencies. Acceptance criteria assert no off-origin `<script src>` or `<link href>` exists on either page; the only script is same-origin `/assets/js/coins.js`. |
| T-24-SC | Tampering (supply chain) | dependency installs | N/A | No package manager, no lockfile, no CDN, no build step — nothing is installed, so no `## Package Legitimacy Audit` is applicable. |

## ASVS L1 categories explicitly N/A for this phase, with reason

**V2/V3/V4** (auth, session, access control) — no accounts, sessions or server-side authorization exist; every page is public static content. **V6/V9** (crypto, comms) — no secrets; TLS is GitHub Pages' and not configurable from this repo. **V8/V13** (data protection, API) — no PII, no backend. **V12** (file upload) — no upload surface. **V7** (error handling/logging) — no server logs. The only applicable chapter is **V5 (Validation, Sanitization, Encoding)**, and these two files contain no dynamic value to validate.
