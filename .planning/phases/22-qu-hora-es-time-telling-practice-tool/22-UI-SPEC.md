## Spacing Scale

Declared values (must be multiples of 4) — matches the values already implicitly used across `styles.css`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, colon side-margins |
| sm | 8px | Compact gaps (nav row gap, reel item internal padding) |
| md | 16px | Card padding, default element spacing (matches `.card { padding: 20px }` ≈ this tier) |
| lg | 24px | Section padding (dial card internal padding, phrase-output card padding) |
| xl | 32px | Layout gaps (space above/below the HH:MM dial block) |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions (both are pre-existing app conventions, not new):
- **44px minimum touch target** — the Repeat button and the "Qué hora es?" primary CTA must have `min-height: 44px`, matching `#btn-mark`, `.btn-wrong`/`.btn-correct`, `.choice-btn` elsewhere in the app.
- **40px reel row pitch** — each non-active value row inside a dial reel is 40px tall (5 × 8px). The active/center row is 64px tall to comfortably exceed the 44px touch-target minimum while leaving room for the larger display digit size below.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (faded reel neighbor values, dial captions) | 16px (`1rem`) | 400 | 1.5 |
| Label (nav links, Repeat button, meta hints e.g. "de la mañana") | 14px (`0.85rem`) | 400 | 1.4 |
| Heading (Spanish phrase output text) | clamp(1.3rem, 5vw, 1.8rem) (~21–29px) | 700 | 1.2 |
| Display (active/centered dial value — the big HH and MM digits) | clamp(2rem, 8vw, 2.6rem) (~32–42px) | 700 | 1.2 |

Exactly 2 weights declared: **400 (regular)** for de-emphasized/neighboring/meta text, **700 (bold)** for the two hero elements (dial digits, phrase output) — reusing the same weight already used by `.target-sentence` and `.qs-choice` elsewhere in the app. (Existing pages also use 600/800 elsewhere, but this phase's new component only needs 2 weights per the design contract — 700 covers both hero roles without introducing a third weight.)

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` `#152238` | Page background (`.hora-page`) |
| Secondary (30%) | `var(--card)` `#121831` | Dial card container, reel background, phrase-output card — matches `.card`/`.qs-end-card` pattern |
| Accent (10%) | `var(--accent)` `#6ca8ff` | Reserved for exactly: (1) the "Qué hora es?" primary CTA button border/highlight, (2) the active/centered dial digit text color, (3) the colon `:` separator is muted, NOT accent — see note below, (4) the active-drag highlight border on whichever dial is currently being dragged (per CONTEXT.md D-04) |
| Destructive | `var(--error)` `#ff6b9d` | Not applicable — Phase 22 has no destructive actions (see Copywriting Contract) |

Accent reserved for: **only** the primary CTA button outline, the active dial's digit color, and the active-drag highlight state. Everything else (Repeat button, Home link, faded neighbor reel values, phrase-output text) uses `var(--muted)` or `var(--ink)` — never accent. This keeps the 10% budget tight and makes the accent color meaningfully signal "the thing you interact with / the value that's live."

Note on colon styling (Claude's discretion per CONTEXT.md): the `:` separator between HH and MM dials uses `var(--muted)` `#aeb6d9`, same size as the active digit display (clamp(2rem, 8vw, 2.6rem)), weight 400, with `8px` (sm token) horizontal margin on each side — it should recede visually so the two accent-colored digit values are what draw the eye.

## Component Specification (supplementary — not in base template, included for executor precision)

These details operationalize CONTEXT.md decisions D-01 through D-04 and the "Claude's Discretion" items, since RESEARCH.md does not exist for this phase.

### Layout (D-03)
- Side-by-side: `[Hour dial]  [ : ]  [Minute dial]` inside one rounded card (`.hora-clock-card`, `var(--card)` background, `border-radius: 16px`, matches `.card`/`.flip-card-front` radius convention).
- Dial reel container width: fixed, enough for 2-digit values (`min-width: 80px`), `overflow: hidden`, `border-radius: 12px`, background one shade darker than the card (`#0f1540`, matching `.stat`/`.result-item` convention) so the reel visually recesses into the card.
- Card padding: 24px (lg token).

### Reel picker (D-01)
- Vertically stacked values, current value centered (64px row height, 700 weight, accent-colored digit).
- Neighboring values (±1, ±2 positions) shown above/below at 40px row height, 400 weight, `var(--muted)` color, with decreasing opacity by distance from center (immediate neighbor: opacity 0.5; second neighbor: opacity 0.25) to reinforce the "scrolling reel" depth cue.
- Drag-to-value ratio: 40px of vertical pointer travel = 1 step (1 hour on the hour dial, 5 minutes on the minute dial) — ties directly to the 40px row-pitch token so the reel visually tracks 1:1 under the finger.
- Release/settle: snaps to the nearest valid step with a 250ms transition, `cubic-bezier(0.4, 0.2, 0.2, 1)` easing (same easing already used by `.nq-card-inner` flip transition, for visual-language consistency).
- Implementation reuses the Pointer Events wiring pattern from `assets/js/locations.js:8-60` (`pointerdown`/`pointermove`/`pointerup`/`pointercancel` on `document`, `setPointerCapture`), adapted from drag-to-drop-zone to continuous value scrolling.

### Active-drag highlight (D-04)
- While a dial is being actively dragged: `border: 2px solid var(--accent)` on the reel container, `transform: scale(1.05)`, `transition: transform 0.15s ease, border-color 0.15s ease` — mirrors the existing tap/press feedback idiom (`.btn:active { transform: translateY(1px) }`, `.flip-card-front:active { transform: scale(0.98) }`) but scales up per the explicit D-04 instruction rather than down, to visually differentiate "actively dragging a reel" from "tapping a button."
- On release, the highlight clears over the same 150ms as the value-settle snap.

### Phrase output card
- Separate card below the dial card (`24px`/lg gap between them), same `var(--card)` background, `16px` border-radius.
- Phrase text: Heading role from Typography table (700 weight, clamp 1.3rem–1.8rem, `var(--ink)` color — not accent, to avoid competing with the dial digits' accent color).
- Repeat button sits directly below the phrase text, right-aligned or centered (`justify-content: center`, matching `.qs-end-actions` convention), disabled/hidden until the first phrase has been spoken (mirrors `.qs-choice:disabled` opacity-0.4 pattern for the disabled state if shown pre-first-tap, though the recommended default is to hide it entirely via `hidden` attribute until first use, matching `.qs-progress` and `.qs-chat`'s `hidden`-until-ready pattern in `quien-soy.html`).

### New home-page button class
- `.btn-hora` — full-width, spans both grid columns, background gradient + accent border, following the exact pattern of `.btn-quien-soy` (`linear-gradient(135deg, #2a1f5a 0%, #1a1440 100%)`, `border: 2px solid var(--accent)`, `font-weight: 700`). Reuse that gradient/border combo verbatim rather than inventing a new one — this phase does not need a visually distinct home-button treatment.
