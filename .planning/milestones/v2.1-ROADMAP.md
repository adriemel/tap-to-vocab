## Phase 22: Qué Hora Es? — Time-Telling Practice Tool

**Goal:** Users can drag hour/minute dials to set a 24h time and hear + see the traditional Spanish phrase for it.
**Depends on:** Phase 21
**Requirements:** HORA-01, HORA-02, HORA-03, HORA-04, HORA-05, HORA-06, HORA-07, HORA-08, HORA-09
**Success Criteria** (what must be TRUE):

  1. A "Qué hora es?" button appears on the home screen below "Quién soy yo" and opens the clock page
  2. The clock page shows two vertical dials (hour 00–23, minute in 5-minute steps) that respond to up/down drag gestures, changing value like a smartwatch alarm picker
  3. Tapping "Qué hora es?" displays the Spanish phrase for the current dial time using traditional phrasing (Es la una / Son las..., y cuarto, y media, menos cuarto/veinte, etc.) plus de la mañana/tarde/noche based on the 24h hour, and speaks it aloud via TTS
  4. Tapping "Repeat" re-speaks the last phrase without changing the dial values
  5. Changing either dial and tapping "Qué hora es?" again produces and speaks the phrase for the new time

## Milestone Summary

**Key Decisions:**

- Traditional Spanish time-phrase grammar isolated as a pure, dual-exported (`window`/CommonJS) module with its own Node test — the highest-correctness-risk surface, proven before any UI was built on top of it
- Reel drag implemented as a value-model (integer index + closure-scoped pixel remainder), never derived from scroll position — matches the project's existing `locations.js` Pointer Events pattern
- Repeat button re-speaks a closure-scoped `lastPhrase` and is sentinel-isolated in the source (`// --- repeat-handler-start/end ---`) to guarantee it never recomputes from live dial state (HORA-08 / RESEARCH Pitfall 4)
- TTS block copied verbatim from `tapvocab.js`'s simple synchronous variant (not `quien-soy.html`'s chained-callback variant), since this page speaks exactly one static string per tap
- `speechSynthesis.resume()` carried over from the Phase 21 iOS TTS fix as cheap, idempotent hardening

**Issues Resolved:**

- None — no regressions or blocking bugs surfaced during execution

**Issues Deferred:**

- `settleTimer` is a single module-level variable shared by both reel-drag closures — latent bug if a user drags one reel then immediately the other (code review warning, non-blocking)
- No `keydown` handler despite `role="spinbutton"`/`aria-value*` attributes on both reels — keyboard/AT users are told arrow keys work but they don't (code review warning, non-blocking)
- No input validation on `minute` in `buildTimePhrase` — unreachable in practice since `getReelValue` only returns fixed-array values (code review warning, non-blocking)
- No `aria-live="polite"` on `#hora-phrase` (code review info item, regression relative to `quien-soy.html`'s pattern for the same kind of update)

**Technical Debt Incurred:**

- The four items above are tracked in `.planning/phases/22-qu-hora-es-time-telling-practice-tool/22-REVIEW.md` and worth a future accessibility/robustness pass
