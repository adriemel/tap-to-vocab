<objective>
Give `topic.html` the ability to filter `data/words.tsv` by its `topics` column via a new `?topic=` URL parameter, while leaving the existing `?cat=` behaviour (including `?cat=practice`) byte-for-byte identical in effect.

Purpose: NAV-06 — "Opening a topic shows every word tagged with it, whichever unidad it came from." Phase 23 shipped the `topics` column; nothing reads it yet. This plan is the read side. The two sub-screens built in Plan 02 are dead links until this exists, which is why this is Wave 1.

Output: a third filter branch in `initFromTSV`, a `topic` key on its `opts` object, a non-blank `h1` for topic pages, and a two-line change to `topic.html`'s inline script.
</objective>

    1. **Read the new opt.** Directly after the existing line `const category = (opts && opts.category) || inferCategoryFromPath();`, add `const topic = (opts && opts.topic) || "";`.

Insert a new `else if (topic)` branch **between** them whose body is `words = shuffleArray(rows.filter(r => (r.topics || "").toLowerCase() === topic.toLowerCase()));`.

       Branch order is load-bearing and must be exactly: practice → topic → category.
       - practice first so `?cat=practice` is never diverted;
       - topic before category so a `?topic=` URL wins even though `category` will be non-empty (see the note below);
       - the existing category branch and its expression must survive **unmodified** — do not add a `|| ""` guard to it, do not merge it with the new branch.

       The `(r.topics || "")` guard is **mandatory**, not stylistic: 171 rows carry `topics: ""` and every practice-list entry rehydrated from `localStorage` has no `topics` key at all, so a bare `r.topics.toLowerCase()` would throw `Cannot read properties of undefined`. This mirrors the project's established `(cols[i] || "").trim()` TSV guard.

    4. **Fix the topic title regression.** Two lines currently read `titleEl.textContent = category === "practice" ? "⭐ Practice" : category;` — one inside the empty-result branch (around line 476) and one just after it on the success path (around line 500). Change the trailing `: category` to `: displayName` on **both**. Keep `titleEl.textContent` — never `innerHTML`.

Without this edit every one of the 9 Topics buttons would render an `h1` reading "topic" (or blank if the fallback ever changes). `displayName` makes it render the topic slug.

    5. **Fix the error wording for the topic path.** In the empty-result branch the error text is currently `"No words found for category: " + category` (with a separate practice message). Make the non-practice message use the word "topic" and the topic slug when `topic` is truthy, and keep the exact existing `"No words found for category: " + category` string when it is not. Keep using `errorEl.textContent`.

The title renders the raw slug, exactly as `?cat=` pages already do. Also do not touch line 354 (`location.href = "/topic.html?cat=practice"` in the quiz-complete modal), do not touch `inferCategoryFromPath`, and do not change the `initBrowseMode(words, category)` call.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query string → page DOM | The only untrusted input this phase introduces. `?topic=` is fully attacker-controllable via a crafted link and flows into `initFromTSV`. |
| same-origin `fetch` of `/data/words.tsv` | Static asset served by GitHub Pages from the same origin. No user input reaches the request path — `tsvPath` is not settable from the URL. |

There is no server, no database, no session, no authentication, and no cross-origin request in this codebase. The only stored state is `localStorage` (`practiceList`, `tapvocab_coins`) and `sessionStorage` (`game_lives`), all of which are already fully user-controlled by design — a user editing their own coin count is not a threat, it is the documented Reset button.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Tampering (DOM XSS via reflected URL param) | `?topic=` → `titleEl` / `errorEl` in `assets/js/tapvocab.js` | mitigate | Both sinks are `Element.textContent`, which cannot execute markup. `assets/js/tapvocab.js` contains **zero** occurrences of `innerHTML`, `insertAdjacentHTML`, `outerHTML` or `document.write` today (verified by grep); Task 1's acceptance criteria assert `grep -c 'innerHTML'` returns 0 so this stays true. The Home button in the empty branch is built with `createElement` + `textContent`, not a template string. |
| T-24-02 | Denial of Service (client-side) | `rows.filter` on an unmatched `?topic=` slug | accept | Worst case is a linear scan of 752 in-memory rows and the existing empty-result branch. No amplification, no server cost, self-inflicted only. |
| T-24-03 | Tampering (crash via untyped data) | `r.topics` is `""` on 171 rows and `undefined` on rehydrated practice entries | mitigate | Mandatory `(r.topics || "")` guard before `.toLowerCase()`, asserted by a grep criterion in Task 1. Without it a `?topic=` navigation would throw and blank the page. |
| T-24-SC | Tampering (supply chain) | dependency installs | N/A | This phase installs nothing. The project is zero-dependency by charter (CLAUDE.md): no package manager, no lockfile, no CDN, no build step. There is no npm/pip/cargo surface to audit and therefore no `## Package Legitimacy Audit` requirement. |

## ASVS L1 categories explicitly N/A for this phase, with reason

- **V2 Authentication / V3 Session Management / V4 Access Control** — no accounts, no sessions, no server-enforced authorization exists anywhere in the app. Every page is public static content.
- **V6 Stored Cryptography / V9 Communications** — no secrets are stored or transmitted; TLS is provided by GitHub Pages and is not configurable from this repo.
- **V8 Data Protection / V13 API** — no PII, no backend API, no persistence beyond the user's own browser storage.
- **V12 File Upload** — no upload surface.
The only ASVS L1 chapter that genuinely applies is **V5 (Validation, Sanitization and Encoding)**, covered by T-24-01 and T-24-03.
</threat_model>
