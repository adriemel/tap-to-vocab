<interfaces>
Layout contract already in the stylesheet — read, not written, except where stated:

`.grid-two-col` is `display: grid; gap: 12px; grid-template-columns: 1fr 1fr;`. Two ordinary non-spanning `.btn` children therefore land side by side with **no new grid rule needed**. Every tool button explicitly opts out of that with `grid-column: 1 / -1` inside its own `.grid-two-col .btn-xxx` rule.

`.grid-two-col .btn` (around line 45) sets `width: 100%; text-align: center; justify-content: center;`. Base `.btn` (around line 134) sets `padding: 12px 16px; background: #1a2350; border: 1px solid #2a3a80; border-radius: 12px; font-weight: 600;`.

**Specificity trap that decides where the new rules go:** `.grid-two-col .btn` and `.grid-two-col .btn-topics` have *identical* specificity (0,2,0). Ties are broken by source order, so a new padding rule only wins if it appears **later in the file** than the rule it must beat. There are two such rules to beat: the generic one near line 45, and the `@media (max-width: 420px)` override near line 1186 that collapses `.grid-two-col .btn` to `padding: 10px 8px`. That is why this plan requires two separate additions rather than one.

`home.js` touches only `#practice-btn`, `#btn-games`, `#coins-msg`, `#btn-reset-coins` — none of the 10 deleted anchors. Deleting them needs zero JS change.
</interfaces>

    **Addition 1 — the height and the gap.** Add a single rule immediately after the existing `.grid-two-col .btn-games` rule (around line 92), so it sits after `.grid-two-col .btn` in source order and therefore wins the specificity tie:
