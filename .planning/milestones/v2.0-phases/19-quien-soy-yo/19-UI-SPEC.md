| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, bubble tail margin, badge padding |
| sm | 8px | Gap between consecutive bubbles, button gap |
| md | 16px | Bubble horizontal padding, container side padding, answer button padding |
| lg | 24px | Chat scroll bottom padding (keeps last bubble above answer strip) |
| xl | 32px | End-screen vertical padding, major section gap |
| 2xl | 48px | End-screen card top/bottom padding on desktop |

- Answer-choice buttons: minimum touch target height 48px (meets WCAG 2.5.5 recommended target)
- Chat scroll area: `padding-bottom: 88px` — approved composite: lg=24px + answer-strip height=64px — functional, not arbitrary
- Home button on index.html: uses existing `.btn` class with `.btn-quien-soy` modifier — inherits 12px/16px padding from `.btn` base

## Color

All values reference existing CSS custom properties declared in `:root` of `styles.css`.

Primary focal point: the incoming question bubble — largest text element, first to animate in on each turn.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` #152238 | Page background, chat scroll area background |
| Secondary (30%) | `--card` #121831 | Question bubble background (left / incoming), end-screen card background |
| Accent (10%) | `--accent` #6ca8ff | Answer bubble background (right / outgoing), active choice highlight, Replay button border |
| Semantic: success | `--ok` #3ddc97 | "¡Muy bien!" heading text color, end-screen success treatment |
| Semantic: muted | `--muted` #aeb6d9 | Bubble timestamp / caption text, progress pill label, disabled state text |
| Semantic: ink | `--ink` #e8ecff | All primary readable text inside bubbles |

Accent (`--accent`) reserved for:
1. Right-aligned answer bubbles (user's chosen response)
2. Replay button border/label on end screen
3. Home button on index.html (`.btn-quien-soy` border, matching `.btn-numbers` pattern)

The `--ok` color is reserved for the end-screen celebration treatment only. No other interactive element in this phase uses `--ok`.

The `--warn` and `--error` colors are NOT used in this phase — there are no wrong answers and no destructive actions.

## Interaction Contract

### Chat flow (CHAT-02 through CHAT-06)

1. Page loads → first question bubble appears with `qs-bubble-in` animation + TTS speaks question (AUDIO-01)
2. Two `.qs-choice` buttons visible in `.qs-answer-strip`
3. User taps a choice:
   a. Both buttons disabled immediately (prevent double-tap)
   b. Chosen answer appended as `.qs-bubble.answer.right` with animation
   c. `scrollIntoView({ behavior: 'smooth', block: 'end' })` on new bubble (CHAT-06)
   d. 400ms delay → TTS speaks chosen answer (AUDIO-02)
   e. 1200ms delay after answer lands → next question bubble appears + TTS reads it
   f. Buttons re-enabled with new labels for next question
4. After question 14 answered → end screen replaces chat view (no transition — hard swap)

### TTS pattern (reuse existing)

```js
// 100ms deferred cancel-then-speak (existing pattern from TTS in conjugation/numbers quiz)
function speak(text) {
  speechSynthesis.cancel();
  setTimeout(() => {
    const utt = new SpeechSynthesisUtterance(text);
    // prefer "Monica" es-ES, fall back to any es voice
    const voices = speechSynthesis.getVoices();
    const voice = voices.find(v => v.name === 'Monica' && v.lang.startsWith('es'))
                  || voices.find(v => v.lang.startsWith('es'));
    if (voice) utt.voice = voice;
    utt.lang = 'es-ES';
    speechSynthesis.speak(utt);
  }, 100);
}
```

### End screen (END-01 through END-06)

- "¡Muy bien!" heading in `--ok` green
- Full intro paragraph: all 14 chosen answers joined with a single space, ending with "¡Muchas gracias por escuchar!"
- TTS auto-plays on end screen load (300ms delay to allow DOM paint)
- Replay button: re-runs `speak(fullParagraph)` — label "↺ Replay"
- Start Again button: resets conversation state, hides end screen, shows chat, loads question 1 — label "Empezar de nuevo"
- Home button: `window.location.href = 'index.html'` — label "Inicio"

## States and Transitions

| State | What the User Sees |
|-------|--------------------|
| Loading | Container visible immediately; no loading spinner needed (data is local file, fast) |
| Question active | Left bubble visible, 2 choice buttons enabled in answer strip |
| Choice tapped | Right bubble animates in, buttons disabled, TTS playing |
| Between questions | Buttons disabled, both bubbles visible, next question pending |
| All answered | End screen (card with heading, paragraph, 3 buttons) |
| TTS unavailable | Silent fallback — layout unchanged, no error shown to user |
| Data load failure | `.error` div with copy: "No se pudo cargar la conversación. Recarga la página." |

## Accessibility

- Answer buttons: minimum 48px touch target height (WCAG 2.5.5)
- Bubble text contrast: `--ink` (#e8ecff) on `--card` (#121831) = ~14:1 ratio (AAA)
- Answer bubble contrast: #0b1020 on `--accent` (#6ca8ff) = ~7:1 ratio (AA large text, acceptable for short conversational text)
- TTS: silent fallback only — no UI change when unavailable
- `aria-live="polite"` on `.qs-chat` for screen reader bubble announcements
- Choice buttons: `aria-label` set to full answer text (not just the short label) for screen reader context
